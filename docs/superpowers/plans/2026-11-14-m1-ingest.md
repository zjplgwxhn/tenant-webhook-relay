# M1: Ingest + 幂等键 + Redis List 入队 + 429/Retry-After 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 实现 webhook 中继 M1：HTTP ingest 接口接收事件，生成并持久化幂等键，有界入队 Redis List，队列满返回 429 + Retry-After。

**Architecture:** 四层自底向上：`idempotency`（幂等键生成）→ `state`（任务领域模型 + Redis hash 存储）→ `queue`（Redis List 有界原子入队）→ `ingest`（HTTP handler 编排）。handler 依赖 `Queue`/`TaskStore` 接口，单测用 fake；Redis 相关单测用 miniredis。

**Tech Stack:** Go 1.22+，`github.com/redis/go-redis/v9`，`github.com/alicebob/miniredis/v2`（测试），`github.com/google/uuid`，`net/http`（stdlib ServeMux）。

**Spec:** `docs/design-webhook-relay.md`（§1.2、§2.1、§2.2）；`docs/implementation-plan.md`（M1）。

## Global Constraints

- 幂等键：生产者带 `producer_key` → `{tenantID}:{producerKey}`；否则 `uuid.NewString()`。
- 队列满 → 429 + `Retry-After`（`clamp(ceil(depth/drainRate), 1s, 60s)`，`drainRate` 下限 1 event/s）。
- 队列是 Redis List（`queue:{tenant}`），每租户有界（默认 10000）。
- 幂等键/任务记录 TTL = 25h。
- Redis 不可用 → ingest 返回 503。
- 本里程碑不做投递/退避/租约（M2+），不做入站去重、签名（设计非目标）。

## Review Focus

1. `Retry-After` 下限：depth=0 时不得返回 0（违反 1s 下限）。
2. `drain_rate` 除零：rate ≤ 0 时 `Compute` 不得 panic、不得返回 0。
3. 幂等键确定性：同一 `producer_key` 重复入站 → 键相同（接收方去重前提）。
4. TTL 对齐：`Put` 后记录 TTL 确实被设置（≈25h），不是永久。
5. 队列满的原子上界：连续 Enqueue 总数不超过 capacity（Lua 原子性）。

type Key string

type KeyGenerator struct {
    NewID func() string
}

func NewKeyGenerator() *KeyGenerator {
    return &KeyGenerator{NewID: uuid.NewString}
}

func (g *KeyGenerator) Generate(tenantID, producerKey string) Key {
    if producerKey != "" {
        return Key(tenantID + ":" + producerKey)
    }
    return Key(g.NewID())
}

**Interfaces:**
- Consumes: `idempotency.KeyGenerator`、`queue.Queue`、`state.TaskStore`、`state.Task`、`state.Status`（Task 1–3）
- Produces:
  - `ingest.RetryAfterCalc` interface：`Compute(queueDepth int64, drainRate float64) time.Duration`
  - `ingest.ClampingRetryAfter{Min, Max time.Duration}`（默认 1s / 60s）
  - `ingest.Handler` + `ingest.NewHandler(keys *idempotency.KeyGenerator, q queue.Queue, s state.TaskStore) *Handler` + `ServeHTTP`
  - HTTP 契约：`POST /v1/events`，头 `X-Tenant-ID` 必填，体 `{"producer_key":"", "payload":{...}}`；202 → `{"task_id":"...","idempotency_key":"..."}`；400 缺租户/坏 JSON；429 满 + `Retry-After`；503 Redis 错。

`ClampingRetryAfter.Compute`：`rate = max(drainRate, 1.0)`；`d := ceil(depth/rate)`；`clamp(d, Min, Max)`。

`Handler` 编排：读租户头 → 解码 JSON → `keys.Generate` → 新 `TaskID`（`uuid.NewString`）→ `queue.Enqueue`（容量门）→ `taskStore.Put`（TTL 25h）→ 202。`ErrQueueFull` → `Depth` + `Compute` → 429 + `Retry-After`。其他 Redis 错 → 503。
