# M2: 租户 worker pool + 全局信号量 + LMOVE + 状态机 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** 实现投递侧：每租户 worker 池从 Redis List 原子出队（LMOVE→inflight），经两级并发控制（租户池 + 全局信号量）向租户下游 POST，并按 2xx/失败写回状态机。

**Architecture:** 新增 `internal/tenant`（租户配置）、`internal/limiter`（两级信号量）、`internal/worker`（Worker + Supervisor）；扩展 `internal/queue`（Dequeue/Ack）与 `internal/state`（StateMachine）。worker 用 `http.Client`（可注入 Transport）投递，携带 `Idempotency-Key` 头。

**Tech Stack:** Go 1.22+，go-redis/v9，miniredis/v2，net/http，httptest。

**Spec:** `docs/design-webhook-relay.md`（§2.1 两级并发、§3.3 状态机）；`docs/implementation-plan.md`（M2）。

## Global Constraints

- At-Least-Once；本里程碑失败立即重入队列（M3 加退避）、无租约/fencing（M4）。
- 每租户 worker 池 size = `Tenant.MaxConcurrency`（默认 8）；全局信号量默认 2048（可配），获取带 100ms 超时。
- 出队 `LMOVE queue:{t} inflight:{t}`（原子）；成功 `LREM inflight:{t}`；失败 `LMOVE inflight:{t} queue:{t}`（立即重入）。
- 状态机仅 M2 转移：`enqueued→in_flight→delivered`（2xx）/ `enqueued→in_flight→enqueued`（失败）。
- 投递 HTTP 超时 20s；2xx 视为成功。
- **Carry-forward（M1 裁决）**：① worker 处理 poison message（`Get` 返回 `ErrNotFound` → 跳过 + 日志 + 计数，不卡死）；② 下游 URL 来自 `tenant.Tenant.Destination`（`Task.Destination` 字段 M2 不用，留作 per-event override）。

## Review Focus

1. Dequeue 原子性：LMOVE 后 task id 落在 inflight，不蒸发。
2. 状态机：终态 `delivered` 上再 Apply 必须被拒（防重复标记）。
3. poison message：队列有 id 但 task 记录不存在 → worker 跳过、不卡死。
4. 全局信号量超时：全局饱和时 `Acquire` 返回 error，不无限阻塞。
5. 租户隔离：一个租户占满自己的 worker 池不影响其他租户。
