# M3: 指数退避 + full jitter + delay 有序集合 + 窗口耗尽 DLQ 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** 投递失败从"立即重入"改为"指数退避 + full jitter 调度到 delay 有序集合"，超过投递窗口则进 DLQ。

**Architecture:** 新增 `internal/backoff`（纯退避计算）、`internal/delayed`（ZSET 调度/轮询）、`internal/dlq`（死信记录）；扩展 `internal/state`（`ScheduleRetry` + `IngestedAt` 序列化）、`internal/tenant`（`RetryWindow`）、`internal/worker`（失败路径 + scheduler）。

**Tech Stack:** Go 1.22+，go-redis/v9，miniredis/v2。

**Spec:** `docs/design-webhook-relay.md`（§3.1 退避、§3.2 窗口、§3.3 窗口给终止）；`docs/implementation-plan.md`（M3）。

## Global Constraints

- 退避：`Base=1s, Factor=2.0, Cap=60s`，full jitter `random(0, min(Cap, Base·2^attempt))`。
- 投递窗口 = `Task.IngestedAt + Tenant.RetryWindow`（默认 24h）；超窗 → DLQ（status `dead`，不再重试）。
- 失败路径（顺序 A，避免"丢失"）：`ScheduleRetry`（status→retry_scheduled + attempt++ + next_retry_at）→ `delayed.Schedule`（ZADD）→ `queue.Ack`（LREM inflight）。
- 下游 429 带 `Retry-After` 头时以该头为准（封顶 60s）。
- scheduler 周期轮询 `delay:{t}` 到期项搬回 `queue:{t}`，并 `Apply(retry_scheduled→enqueued)`。
- 时间戳用 unix nano（int64 字符串）序列化。

## Review Focus

1. full jitter 上界：`Next` 永不超 `Cap`，且 `0 ≤ 值 ≤ min(Cap, Base·2^attempt)`。
2. `ScheduleRetry` 原子性：仅当 status==in_flight 才写，否则 ErrConflict。
3. delay Poll 原子性：到期项 ZREM + LPUSH 不重复、不丢。
4. 窗口判断：`next_retry_at` 超窗 → DLQ，不重新调度。
5. 429 Retry-After：无该头时走退避，有该头时按该头（封顶）。
